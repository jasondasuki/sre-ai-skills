# Profile: triage

The report format for a workload triage: one workload, one conclusion, and the
checks that earn it. Read this when the brief names this profile (Step 3 of the
core). The shared page rules, hard rules, and verification are in the core; this
file holds what is specific to this format.

## Contents

- Title and file name
- Sections, in order
- What the page must not do

## Title and file name

**Report title (required):**

```
YYYY-MM-DD HH:MM UTC - <namespace>/<workload>: <symptom>
```

- **Date and time** are when the triage started, in UTC. Always say `UTC`. The time
  the report was generated goes in the header and footer, not the title.
- **Workload** is the resource the user named (or the owner it resolved to), with
  its namespace. **Symptom** is a few plain words ("43 restarts, probe timeouts",
  "ImagePullBackOff"). Keep the title under about 110 characters, trimming the middle
  rather than the ends: the full workload name and the symptom both matter.
- Use this exact string in the `<title>` element and the page `<h1>`. It is a
  deliberate exception to any short-title guidance in `{{PAGE_DESIGN_SKILL}}`.

**Filename:** `YYYY-MM-DD-HHMM-<namespace>-<workload>-<symptom-slug>.html`, using the
same date and time as the title (UTC) and short kebab-case slugs, for example
`2026-10-04-2318-shop-queue-cache-probe-restarts.html`. Never overwrite an existing
report; if the name exists, append `-2`. For a follow-up on the same workload, write
a new file and link back to the earlier one.

## Sections, in order

1. **Header:** the `<h1>` is the report title. Beneath it: the cluster context the
   triage ran against, the target (namespace, kind, name), the time the report was
   generated, a confidence pill (high / medium / low, left out when healthy), and
   a status pill derived from it: cause found (high or medium), inconclusive (low,
   or no cause), or healthy (nothing is broken).
2. **What is broken:** the answer card. One or two sentences, plain. If nothing is
   broken, say so and say what was checked.
3. **At a glance:** a short row of stat tiles from the workload's own state: ready
   count, restarts, age, last termination reason and exit code, node. Only values
   actually read.
4. **Evidence:** the line that proves the cause, set apart and quoted exactly as the
   findings give it (customer or personal values already `<redacted>`), with the
   command it came from. Then one entry per check that mattered: the command,
   the window, and the result in one line. Raw output goes in a monospace block that
   scrolls on its own; trim it to the lines that carry the point.
5. **Timeline:** restarts, events, and state changes in UTC, when the cluster
   recorded them. Leave the section out, with one line saying so, when it recorded
   none.
6. **Narrowest fix:** the smallest change that addresses the cause, who applies
   it, and whether it is reversible (yes, no, or partly). This skill proposes, the
   owner applies.
7. **Not verified:** what could not be seen, or the next check when the result is
   inconclusive.
8. **Created:** the debug containers added to the workload, by name, or "nothing;
   read-only". They stay listed on the workload until it is recreated, so the reader
   needs to know.
9. **Final root cause:** the closing chain exactly as the findings give it:
   trigger, mechanism, and recovery with their UTC times, then contributing
   factors, still open, and confidence. Show each "not established" link as
   written; never fill it in. It agrees with the answer card.
10. **Footer:** generated by the producing skill (named in the brief); the cluster
    context; how many commands were run; and the model that actually ran.

## What the page must not do

- Reproduce a Secret, a token, an environment value, or a connection string. Say
  that it exists and where.
- Reproduce customer or personal data (emails, names, message bodies, request
  payloads) from a log line. Show the line's shape with those values replaced by
  `<redacted>`.
- Show a chart. A triage reads live state at one moment, so there is no series to
  plot; stat tiles and quoted lines are the honest form.
- Present a number without the command that produced it.
